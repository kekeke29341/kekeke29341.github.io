Llama 3.1 や Mistral、Qwen など、今手元で動かしているデコーダLLMのほぼ全部が、位置情報に **RoPE**（Rotary Position Embedding）を使っています。論文は Su らによる RoFormer（2021）です。要点は短く言うと、「位置をベクトルに足す」のではなく、「Query と Key を位置に応じて回す」ことです。

この記事では、なぜ回すのか、内積に何が残るのか、長い文脈を伸ばすときに何が壊れるのか、までを実装寄りの順で書きます。

## 位置がないと、語順が消える

Self-attention は、トークンの集合に対する重み付き和です。位置を何も足さないと、

- 「猫が鼠を追う」
- 「鼠が猫を追う」

の区別が、語彙の共起だけでは残りません。そこで位置を何らかの方法で Q / K（必要なら埋め込み）に混ぜます。

古典的なやり方は **絶対位置** です。正弦波を足す（元の Transformer）、あるいは位置ごとの学習ベクトルを足す。どちらも「今何番目か」は分かりますが、「どれだけ離れているか」はモデルが後から学ぶ必要があります。学習時より長い系列に出すと、見たことのない位置IDが出て、外挿が急に崩れます。

欲しいのは多くの場合、絶対番号ではなく **相対位置** \(m - n\) です。RoPE は、回転という操作でこれを内積の中に直接入れます。

## 2次元なら、回転そのもの

いちばん小さい例は2次元です。角度 \(\theta\) の回転行列は次です。

$$
R_\theta = \begin{pmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{pmatrix}
$$

位置 \(m\) の query、位置 \(n\) の key を、それぞれ \(m\theta\)、\(n\theta\) だけ回します。

$$
q_m' = R_{m\theta}\, q, \qquad k_n' = R_{n\theta}\, k
$$

回転行列は直交なので、内積はこう簡約されます。

$$
\langle q_m', k_n' \rangle = \langle q,\, R_{(n-m)\theta}\, k \rangle
$$

左辺は「位置 \(m\) と \(n\) で回したあとの類似度」、右辺は「元の \(q, k\) と、**差** \(n-m\) だけの回転」です。絶対位置 \(m\) と \(n\) は消え、相対位置だけが残ります。これが RoPE の核です。

複素数で書くと同じことで、\(q\) を \(e^{i m \theta}\) 倍する、と読めます。回転はノルムを変えないので、位置を足したときにベクトルの長さが歪む、という副作用がありません。

## 高次元では、2次元ずつ周波数を変えて回す

head 次元 \(d\) は偶数前提で、\(d/2\) 枚の2次元平面に分けます。平面 \(i = 0, \ldots, d/2-1\) ごとに角度の進み方を変えます。

$$
\theta_i = \mathrm{base}^{-2i/d}
$$

Llama 系の既定は \(\mathrm{base} = 10000\) です。\(i\) が小さい平面は波長が長く、離れたトークンの関係を持ちます。\(i\) が大きい平面は波長が短く、近所の語順に敏感です。正弦波の絶対位置埋め込みと同じ発想で、スケールを層状に持たせています。

実装では、位置 \(m\) に対して各平面の \(\cos(m\theta_i)\) と \(\sin(m\theta_i)\) をキャッシュし、偶数次元と奇数次元を組にして回します。Hugging Face の Llama 実装に出てくる形は、だいたい次です。

```python
def rotate_half(x):
    x1, x2 = x[..., ::2], x[..., 1::2]
    return torch.stack((-x2, x1), dim=-1).flatten(-2)

def apply_rope(x, cos, sin):
    return x * cos + rotate_half(x) * sin
```

`x` は Q または K です。**V は回さない**のが Llama / Mistral 系の標準です。Attention の重み（どこを見るか）に相対位置を載せ、集める中身そのものは位置でひねらない、という分担です。

## 他の位置エンコーディングとの位置づけ

| 方式 | 何を混ぜるか | 相対位置 | 長い文脈 |
| --- | --- | --- | --- |
| 正弦波 / 学習 PE | 埋め込みに加算 | 間接 | 未学習の位置IDで崩れやすい |
| ALiBi | スコアに距離バイアス | 明示 | 外挿は比較的素直 |
| RoPE | Q/K を回転 | 内積に自然に出る | 伸ばす方法を選ぶ必要あり |

ALiBi は「遠いほど減点」をスコアに足します。単純で外挿も強い一方、距離の効き方は線形バイアスに固定されます。RoPE は距離を周波数の重ね合わせで表すので、表現力は高いですが、学習時の最大長を超えたときの振る舞いが素直ではありません。

## コンテキストを伸ばすと、何が起きるか

学習が 4k や 8k まででも、推論で 32k や 128k を出したくなる、というのがここ数年の実務です。RoPE では位置 \(m\) が大きいほど回転角 \(m\theta_i\) が学習分布の外に出ます。特に波長の短い平面から先に「見たことのない角度」になります。

よく使う伸ばし方は次の三つです。

1. **位置の線形補間**  
   位置を \(m' = m \cdot L_{\mathrm{train}} / L_{\mathrm{infer}}\) に縮める。角度は学習範囲に収まるが、近いトークンの解像度が落ちる。
2. **NTK-aware scaling**  
   高周波はあまり触らず、低周波側の base を実効的に上げて波長を伸ばす。近所の語順を保ったまま、遠い依存だけを伸ばしたいときに使う。
3. **YaRN**  
   周波数帯ごとに補間と外挿を分け、注意温度も合わせて補正する。長文対応の公開モデルでよく見る手法です。

カタログの「32k 対応」は、このどれか（または追加学習）が入っている、という以上の意味ではありません。閉域で長文RAGを載せるときは、**どの RoPE スケーリングか**と、学習長を超えた区間の評価セットを分けて見る必要があります。埋め込みの次元や GQA の head 数より、ここで精度が落ちることがあります。

base そのものを大きくするモデルもあります（長文向けに 5e5 や 1e6）。同じ「RoPE です」でも、\(\theta_i\) のスケールが違うと、同じ位置 \(m\) の回転角が違います。推論エンジン側の RoPE 設定を、重みの `rope_theta` / `rope_scaling` と食い違わせると、黙って品質だけ落ちます。vLLM や TensorRT-LLM で変な出力が出たときは、まずここを見ます。

## 運用で見ておく場所

- Hugging Face の `config.json`: `rope_theta`, `rope_scaling`（`type`, `factor`）
- 実装: `apply_rotary_pos_emb`。Q/K の head 次元が偶数か、GQA で KV head にも同じ回転をかけているか
- 量子化後: 回転は `cos` / `sin` との積なので、Q/K のスケールが崩れると位置情報が先に死ぬ。長文だけ急に壊れるときは、RoPE 近傍の精度を疑う
- キャッシュ: `cos` / `sin` は位置の関数なので、KV cache と一緒に「今何トークン目か」がずれないこと。prefix cache や sliding window と組み合わせるときは、絶対位置の基準を揃える

## まとめ

RoPE は、位置 \(m\) で Q/K を回転し、内積に相対位置 \(n-m\) だけを残す仕組みです。ノルムを保ち、周波数を平面ごとに分け、今のデコーダLLMの標準になっています。

モデルカードの「長文対応」は、RoPE の伸ばし方の話であることが多いです。ローカルLLMを閉域に載せるときは、モデル名より先に `rope_theta` と `rope_scaling` を重みとエンジンで一致させ、学習長の内側と外側を分けて評価するのが安全です。
